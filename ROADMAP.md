  *Accept when:* one message with buttons replaces the page spam, presses swap the embed in place, the viewer filter still applies per button, and a press by anyone works (help is public, so no owner gate).

- [x] **M20 — Chat kill counter** 💀 *(S99)* — when a channel goes **30 seconds silent** after someone speaks, that person scores 1 point: they "killed" the chat. Plus a leaderboard. Design notes for whoever builds it: the timer must be per channel and reset on every new message; scoring must be idempotent (one point per silence, not one per timer tick); and the counter should ignore the bot's own messages and probably command invocations. Owner has not specified whether it runs in every channel or a configured set — **ask before building** if it is not obvious from the precinct's usage.

- [x] **M22 — Maintenance mode shows in the bot's status** 🔧 *(S98)* *(owner request, arrived during S97)* — set the bot's **presence** so anyone can see at a glance whether CuffBot is in maintenance mode or on normal duty, without typing anything. Maintenance is per-guild (`maintenanceConfig`) but presence is per-BOT and global, so the presence reflects the home precinct's state — which is the whole precinct, CuffBot being single-guild by design (S1). Set it at boot and on every `!maintenance on/off`.
  *Accept when:* the presence flips within a second of the toggle, survives a restart (read from storage at boot, not from a variable), and the maintenance manual says what each status looks like. Suggested shapes: normal → Online + "Watching the precinct"; maintenance → Do Not Disturb + "🔧 Maintenance — bot owner only". Pure status-building logic in `lib/` with tests; the presence call itself is one thin wrapper.

- [x] **M23 — Connect4 solo mode** 🔴 *(S100)* *(owner request, arrived during S97)* — play `!connect4` against the **bot** instead of another member. The module already has the board, the win detection and the button pump (S71/M16.3); what is missing is an opponent. Build the AI as **pure logic in `lib/`** — `chooseMove(board, disc)` taking the same board the game engine uses — so it is fully testable without a gateway, then wire one extra entry point (`!connect4 solo [difficulty]`). Suggested opponent: a short minimax with alpha-beta over the 7 columns (the board is tiny, depth 5–7 is instant even on a Pi) plus an immediate win/block check; difficulty = search depth, so `easy` can simply be depth 1 with a random tiebreak.
  *Accept when:* the AI never plays an illegal column, always takes an immediate win, always blocks an immediate loss, plays instantly on a Pi at the default difficulty, and the whole opponent is covered by pure tests with fixed boards (no timing, no gateway). A solo game must be a normal game to the rest of the module — same board rendering, same buttons, same win handling.

- [ ] **M21 — Speech to text** 🎙️ *(owner marked LOWEST priority)* — transcribe voice-chat audio and voice memos to **English**. ⚠️ **This one needs an owner decision before any code:** it is the first feature that cannot be built with zero dependencies. Receiving voice needs `@discordjs/voice` plus an opus decoder, and transcription needs either a local model (Whisper-class — heavy for a Raspberry Pi) or a paid/free-tier cloud API. The two halves can also be split: **voice memos** (attached audio files) are much simpler than **live voice chat** and could ship alone. Bring the owner a short options list — dependency footprint, Pi feasibility, cost — and let them choose before building.
